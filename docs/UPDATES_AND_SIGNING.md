# PIXUBI — оновлення поверх гри без втрати вихованця

## Чому 0.1–0.5 не можуть оновлюватися одна одною
Перші збірки мали різні package IDs (`com.pixubi.game`, `.preview`, `.sound`, `.visual`, `.quiz`) і тимчасові debug-ключі.
Android вимагає однакового applicationId, сумісного підпису та більшого versionCode. Прості кнопки не можуть обійти захист Android.

## Як працюватиме стабільна PIXUBI
- Стабільний applicationId: `com.pixubi.game.stable`; незмінний підпис.
- Кнопка у Settings перевіряє `https://api.github.com/repos/MrKanzo/PIXUBI/releases/latest` лише за запитом або раз на день.
- Якщо є пізніша версія, пропонує завантажити `PIXUBI-release.apk`, перевіряє файл, підпис і версію, відкриває системний інсталятор.
- Гра залишається повністю придатною без інтернету: потреби, сон, сплячка, вікторини і музика локальні.
- Офіційний реліз розповсюджується через GitHub Releases; для Google Play потрібна інша політика оновлення.

## Одноразове налаштування підпису (власнику)
Ніколи не надсилай keystore, його паролі чи вміст через чат, публічний репозиторій або Issues!

1. Створи keystore локально на довіреному ПК/Termux із Java keytool:
   `keytool -genkeypair -v -keystore pixubi-release.jks -alias pixubi -keyalg RSA -keysize 3072 -validity 10000`
   Обери надійний пароль; на запит пароля ключа можна використати пароль сховища.
2. Зроби **офлайн резервну копію** .jks та паролів: якщо їх втратити, майбутні APK неможливо підписати тим самим ключем.
3. У GitHub: `MrKanzo/PIXUBI → Settings → Secrets and variables → Actions → New repository secret`.
4. Додай **чотири приватні Secrets** (без лапок, і НЕ в репозиторій):
   - `PIXUBI_KEYSTORE_BASE64` — base64 вміст keystore (наприклад `base64 -w 0 pixubi-release.jks` на Termux/Linux).
   - `PIXUBI_STORE_PASSWORD` — пароль сховища.
   - `PIXUBI_KEY_ALIAS` — `pixubi`.
   - `PIXUBI_KEY_PASSWORD` — пароль ключа.
5. У GitHub Actions запусти `PIXUBI Android APK` через **Run workflow**. Якщо secrets встановлені, збірка підпише release APK та опублікує `v0.6.0` у GitHub Releases.
6. **Перший раз** встанови підписану стабільну PIXUBI 0.6 окремо. Наступні `v0.6.1`, `v0.7.0` мають той самий applicationId, ключ і більший versionCode — вони оновлюватимуться поверх, зберігаючи приватні дані застосунку.

## Тестування
Поки GitHub Secrets не налаштовані, Actions збирає лише debug-APK з ID `com.pixubi.game.stable.preview`. Цей файл тестує екран і не може оновлювати стабільну версію. Перевір: відкривати налаштування, натискати «Перевірити оновлення», отримувати зрозуміле повідомлення без релізу; перевіряти офлайн догляд і музику.

## Безпека
- Не публікуй keystore й паролі. Публічний витік дозволить стороннім створювати шкідливі «оновлення».
- Наявність нового GitHub Release не означає автоматичної установки: її завжди підтверджує користувач.
- При зміні package ID чи ключа — це вже інший застосунок. Міграцію старих тваринок слід проєктувати окремо.
